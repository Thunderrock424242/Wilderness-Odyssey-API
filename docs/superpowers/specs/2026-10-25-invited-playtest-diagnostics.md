# Invited playtest diagnostics

Approved scope: invitation enrollment, no required Minecraft ownership verification; client collection in single-player and multiplayer; staff controls on the existing signed-in website; separate session summaries, logs, crashes and Spark artifacts on each tester profile. Bot and website changes are handed to their respective branches. Implement the Minecraft side here without deploying external services.

The client owns its installation credential, consent and local stop. The backend owns invitation redemption, tester/campaign membership, revocation and durable report storage. A displayed Minecraft name/UUID is reported metadata, never proof of ownership. Existing server telemetry remains a separate server-owned producer.

Use an outbound HTTPS API (HTTP allowed only for literal loopback development). Enrollment is a one-time invitation redemption. Subsequent requests use an installation-scoped bearer credential. Never embed a staff token or Discord webhook in a client. No arbitrary remote commands, file paths or upload URLs are accepted.

Capture only during an acknowledged enabled policy with a monotonic lease capped at 60 seconds. Poll every 10 seconds on one client-owned daemon I/O worker; no network/file I/O on client ticks. Off/revocation/local stop discard pending diagnostic payloads, cancel this feature's Spark sampler, and stop capture. An independent worker enforces expiry even if rendering stalls. Previously received backend artifacts are retained. Vanilla local logging is unaffected.

Sessions are client-generated UUIDs. Each immutable artifact has a stable UUID, campaign/tester/collection/session IDs, kind (`session`, `log`, `crash`, `spark`), scope `client`, capture times and content. Every off/on cycle creates a new backend collection ID, fencing stale queued data. Backend deduplicates artifact IDs and checks current authorization. Logs filter recognized chat messages, redact recognized secrets and paths, and are capped at 256 KiB per artifact. Queue at most 16 artifacts / 8 MiB on disk; Spark files at most 1 MiB. No arbitrary crash folder sweep: interrupted recovery uses only our previously saved redacted session tail, and cannot guarantee the crash's final messages.

Spark is optional and compatibility guarded. Operate only the client Spark platform discovered through its registered `sparkc` command, never the global provider (which may refer to the integrated server). Do not replace/stop a sampler started by another owner. Export local `.sparkprofile` files; send them as separate artifacts to our backend, never silently publish to the public Spark host. Record unavailable/busy/export-failed honestly. Segment captures at 120 seconds, rechecking current lease before retaining/exporting data. Normal logout finalizes; hard termination can only recover persisted information on next launch if the backend still authorizes that exact campaign/tester.

One accessible Playtest screen accepts the API origin and invitation without chat commands containing secrets, explains collection, and offers consent/enrollment and local stop. Title/pause menu access plus `/woplaytest` fallback and visible recording status. Enrollment is local installation state, outside synchronized configs.

Reuse NeoForge client event registration, Minecraft's client thread for Minecraft/Spark command discovery, the existing bounded HTTP response handler and project JUnit task. Client-specific lifecycle requires its own single owned worker because existing async telemetry workers belong to a live logical server and are unavailable at the title screen.

Acceptance: loopback HTTP contract tests; lease expiry, denied policy, changed campaign, stale response after local stop, redaction/chat filtering, queue bounds/recovery/idempotence, enrollment origin validation, logout and interrupted recovery. Compile with JDK 21 and run focused playtest tests serially. Real clients, installed Spark and external services remain separate acceptance tests.
