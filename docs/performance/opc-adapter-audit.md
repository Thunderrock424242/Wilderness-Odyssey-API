# Odyssey Performance Core: Data, Simulation, and feature adapter audit

Audit date: 2026-10-17. This is a source audit of the working checkout, performed before the corresponding OPC integration changes. References identify the inspected source; line numbers may move during implementation. No Gradle process, Minecraft session, benchmark, or gameplay acceptance run was executed for this audit.

## Scope and confidence

This audit covers `dataengine/`, `simulation/`, and their ecosystem, weather, water, and vegetation consumers. Paths below are relative to `src/main/java/com/thunder/wildernessodysseyapi/` unless another root is stated. Tick Engine, Background Efficiency, AsyncTaskManager executor internals, the existing Performance Coordinator, and save ownership are audited separately. Their callers are included here where they constrain integration.

**High confidence** means a direct source control-flow or caller observation. **Profiling needed** means source identifies work or a possible starvation mechanism, but its actual cost/frequency is unmeasured. Absence of a caller means no in-repository production caller was found; it is not evidence that a public API has no external consumers.

The safe consolidation boundary is shared admission, deadlines, lifecycle coordination, and diagnostics. Feature-owned due queues, ledgers, revision validation, attachment persistence, packet schemas, and gameplay authority should remain with their existing owners.

## Real registration and caller map

### Bootstrap, configuration, and lifecycle

- `core/WildernessOdysseyAPIMainModClass.java:80` bootstraps population ecology once. Lines 119-126 explicitly register ecosystem, distant wildlife, performance, and server lifecycle event classes. Weather and vegetation event bridges use `@EventBusSubscriber`, so OPC must not additionally register them.
- `server/ServerLifecycleEvents.java:53-61` initializes Background Efficiency, Tick Engine, Data Engine, ecosystem/weather/water registrations, then Simulation Engine. Population's `onServerStarted` registers its Data Engine async-only owner ID (`simulation/integration/PopulationEcologySimulationSystem.java:222-232`). Preserve this order and exactly-once registration.
- `server/ServerLifecycleEvents.java:75-99` advances mandatory clocks before optional work, drains the existing async main-thread queue, then Data Engine, then optional Riftfall work while NeoForge reports spare time. OPC must not absorb mandatory clocks into a disposable lane.
- `server/ServerLifecycleEvents.java:105-129` captures SPH persistence, stops simulation, then shuts down Tick, Background, Data, and async services. `WeatherServerEvents.java:83` separately shuts down weather adapter/authority; `DistantWildlifeServerEvents.java:79` shuts down ecosystem adapter/managers. Preserve idempotence and late-result rejection across this event ordering.
- `config/ModConfigRegistration.java:102` reloads simulation on the server thread; line 125 reloads Data Engine values. `DataEngine.reload` preserves structural queue bounds until restart. `dataengine/config/DataEngineConfig.java` attaches legacy/public `CONFIG_SPEC` to unified performance config. Do not recreate duplicate specs or discard queued work on reload.

### Data Engine consumer details

- Debug: `dataengine/debug/DataEngineDebugIntegration.java:28-75` schedules every 20 ticks, marks one dirty key, snapshots metrics, and sends to explicit subscribers. `dataengine/network/DataEnginePayloads.java` updates feature interest from the client debug subscription packet. `debug/client/DataEngineDebugClientEvents.java` sends the subscription and registers the debug delta receiver.
- Ecosystem: `ecosystem/integration/EcosystemPerformanceIntegration.java:46-58` schedules maintenance and handles dirty client refreshes. `ecosystem/distant/DistantWildlifeManager.java:141` marks client state dirty after lifecycle changes. This path preserves its existing distant-wildlife codec and ledger rather than sending DataDelta bodies.
- Weather: `weather/integration/WeatherPerformanceIntegration.java:194-206` submits a coalesced callback per loaded level; line 282 submits detached calculation; line 427 marks snapshot publication dirty. Negative snapshot keys and positive level-maintenance keys do not collide. `WeatherAuthority` remains the only weather simulator.
- Water: `watersystem/water/integration/WaterPerformanceIntegration.java:173-190` submits separate coalesced level/lane callbacks; `taskKey` uses a stride of eight and monotonic session level IDs. Due timestamps advance only after successful work. Rejected submissions remain due for the next poll.
- Simulation: `simulation/core/SimulationEngine.java:119-125` supplies one five-tick Data Engine poll. Adaptive policy normally runs a regional pass at 20 ticks. `PopulationEcologySimulationSystem.java:204` uses async work with its own owner ID, generation, region, settings, and ledger validation.
- Vegetation: `vegetation/network/ReactiveVegetationSyncService.java:42-62` receives a chunk-watch event, creates an owner payload only for existing attachment data, and selects `ReactiveVegetationSnapshotTransport.queueInitial`. Visual changes at line 80 continue through tracking-chunk publication.
- Diagnostics: `diagnostics/performance/PerformanceDiagnostics.java:218`, `weather/debug/WeatherDebugCommand.java:270`, and the Data Engine command consume metrics. `debugoverlay/provider/PerformanceDebugDataProvider.java:111` consumes simulation diagnostics.
- Searches found no production call to root `registerCache`, no production spatial `DataEngine.sendDelta(region, profile, delta)` invocation, and no additional concrete `SimulationSystem` participant. Preserve external extension points despite these adoption limits.

### Feature-owned paths outside Data Engine

- `ecosystem/distant/DistantWildlifeServerEvents.java:21-33` calls `EcosystemSimulationManager.tick` every tick to restore/reclassify player-visible wildlife immediately. It then invokes optional fallback only when Data Engine is disabled. Optional maintenance (`EcosystemPerformanceIntegration.java:114-117`) calls the existing simulation manager and distant manager. These are complementary paths, not duplicate full simulation passes.
- `weather/simulation/WeatherServerEvents.java:28-40` invokes the disabled-engine fallback and runs `WeatherAuthority.tickWorldEffects` with the live allowance. Player login, dimension change, respawn, and logout mark/forget owner sync state. Level unload clears adapter handles and owner caches (`:77`), and shutdown clears both (`:85`).
- `watersystem/ocean/WaterWeatherServerEvents.java:27` provides lowest-priority disabled-engine fallback. `watersystem/water/sph/ServerTickHandler.java:58` forgets unloading adapter levels. Actual water authorities, SPH collision/motion, finite-volume updates, and native persistence remain outside this wrapper.
- `vegetation/simulation/ReactiveVegetationEvents.java:22-35` owns chunk admission/removal. Its `ServerTickEvent.Post` handler calls the owner scheduler directly (`:40-47`); unload/stop clear schedules and disturbances. Do not invent a second loaded-chunk index.

## Integration invariants

1. Preserve Data Engine enabled/disabled behavior, public facades, submission return values, dirty identities, immutable task contracts, wire payload IDs, handler registration, and restart cleanup. Consolidating names does not authorize breaking API consumers.
2. Keep weather preparation/application, ecosystem ledgers, vegetation attachments, and water mutation on the owning server thread. Only detached immutable weather/population computation belongs on workers. Reuse AsyncTaskManager; do not create another pool.
3. Preserve disabled-engine fallbacks. Weather fallback abandons the in-flight token and requests an owner retry before synchronous maintenance. Water fallback rechecks allowance between due lanes and advances only completed lanes. Ecosystem fallback leaves immediate player/AI work active. Vegetation falls back to direct initial snapshot publication after rejected batching.
4. Keep current gameplay defaults. Data Engine, network batching, and population ecology currently default enabled. A new performance admission facade must not make population ecology or weather silently disappear when optimization is disabled.
5. Keep native/feature persistence authoritative. Periodic SPH captures are optional maintenance, while shutdown captures happen independently before teardown. No budget may skip required persistence or take over Minecraft save/chunk lifecycle.
6. Retain current-session and current-level checks. Weather rejects stale batches by submission token plus owner revision; population checks generation and ledger revisions; water queues validate level-handle identity. An unloaded/recreated dimension with the same ID is not the same live world.
7. Preserve per-feature semantics rather than unifying every queue. Data dirty updates represent final state; water lanes represent due owner work; simulation requests deduplicate regions; vegetation due entries retain loaded-chunk sample schedules. A common policy can admit them without erasing those meanings.
8. OPC diagnostics must distinguish queue wait, server-thread preparation/apply, worker computation, owner simulation, packet traffic, and dropped/superseded results. An admitted wrapper is not evidence its nested owner completed within the deadline.

## Validation and profiling priorities

Existing focused tests are under `src/test/java/com/thunder/wildernessodysseyapi/`: Data Engine scheduler, queue, dirty, interest, async worker, cache, metrics, packet codec, and diagnostic benchmark; Simulation region manager, registry, coordinator, event dispatcher, and population model; feature adapter tests for ecosystem, weather, water; vegetation scheduler and sampling tests. `DataSyncManager` itself has no dedicated test class in that inventory, so codec tests alone do not establish batching fairness, recipient lifecycle, or configured packet admission.

Run the smallest relevant tests through the checked-in Gradle wrapper with `'-PcodexBuildDir=.codex-build' --no-parallel`, with exactly one Codex-controlled Gradle process. Source inspection is not passing-test evidence. A failed unrelated integration/environment step must be reported separately.

Profiling order:

1. Record per-lane executed/deferred counts, maximum callback duration, queue age, network oldest pending age, and rejected completions during idle, ordinary play, multi-dimension exploration, and chunk-pressure scenarios.
2. Measure zero-subscriber diagnostics allocation and elapsed time before/after the guard. Confirm subscribed debug pages still update and subscriptions clear on logout.
3. Measure vegetation chunk update duration and simulation region context construction separately from queue admission. Identify whether inner work needs finer-grained budgets.
4. Exercise disabled/re-enabled performance settings, world unload/reload, player dimension changes, disconnect, and integrated-server restart with accepted worker calculations still pending.
5. In a disposable real world, verify weather/hydrology conservation receipts, finite-water flow/projection, wildlife AI restoration/form transitions, vegetation initial and changed visuals, and final save/reload. Existing owner GameTests should remain the first runtime regression layer.

No throughput gain, tick-time improvement, full-modpack compatibility, existing-world safety, client rendering correctness, multiplayer synchronization, or long-session performance was established by this read-only audit. Those require current-artifact tests and measured runtime evidence.
