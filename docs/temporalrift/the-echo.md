# Echo Earth

Echo Earth is a real parallel Earth that developed independently alongside the player's Earth. Its geology can be familiar while its human history differs. The design principle is **familiar before impossible**: recognizable terrain first, structural differences later, and eventually evidence of material synchronization.

The resource key remains `wildernessodysseyapi:the_echo`, and the generator codec remains `wildernessodysseyapi:echo_noise`. Existing dimension folders, teleport routes, pending build echoes, The Before, and Temporal Rift mechanics retain their identities.

## Internal lore — not an arrival speech

Echo Earth existed before contact. A military/scientific experiment created a wormhole or fracture between the two Earths. Contact destabilized both realities and began forcing them toward synchronization. Echo Earth is neither a memory nor a magically generated copy. The experiment's history is an eventual recovered-record discovery; ordinary travel does not unlock it.

## Audit and extension boundaries

The original `EchoChunkGenerator` already used the world seed, Overworld noise settings and the Overworld multi-noise biome preset. That terrain path is retained. Its new structure-state override uses Minecraft's **normal** structure state factory, preserving level and concentric-ring seeds for shared sets.

The old atmosphere used uniformly dark fog, heavy sky/cloud tint and cancelled every sound category except players and neutral animals. The dimension type also fixed time at noon and selected the End sky renderer. Presentation now reads a server-authored local stability summary and uses the ordinary Overworld celestial renderer.

The previous chunk decorator was already new-chunk-only and palette-aware, but still examined every block in each relevant section. It now samples at most sixteen narrow surface columns. The original build-echo ledger was unbounded, scanned its entire queue once per day, and used a process-global day marker. The ledger remains the owner but now coalesces, bounds and rotates scheduled work.

## Geography and independent structures

Same seed, default Overworld noise and the shared biome preset keep mountains, valleys, coasts and general biome regions aligned. This does not clone arbitrary third-party Overworld generators: generators or biome integrations that explicitly discriminate by dimension can diverge. No existing terrain or structures are regenerated.

`EchoStructurePolicy` is a registration-time content API for **structure-set IDs**, not template file names or individual structure IDs:

| Mode | Earth | Echo Earth |
| --- | --- | --- |
| `SHARED` | Original set | Original set |
| `EARTH_ONLY` | Original set | Excluded |
| `ECHO_ONLY` | Excluded | Original set |
| `ECHO_VARIANT` | Original set | Authored alternate set |

Unregistered sets are shared by default. Register definitions during common setup, before worlds open:

```java
EchoStructurePolicy.register(
        ResourceLocation.parse("example:earth_settlements"),
        EchoStructureMode.EARTH_ONLY);
EchoStructurePolicy.registerVariant(
        ResourceLocation.parse("example:towns"),
        ResourceLocation.parse("example:echo_research_facilities"));
```

The example IDs are illustrative and must already be supplied by actual registered structure content. No unfinished facilities, roads, bunkers, cities, camps or accelerator templates are generated by this upgrade. The framework supports their later addition. Matching a town's coordinates with a facility requires the content author to match placement parameters and compatible biome constraints; this is not automatic template conversion.

Variants automatically make their target set Echo-only. Missing optional variant targets fall back to the original set. Conflicting registrations fail explicitly. A narrow `EarthStructurePolicyMixin` filters the Overworld's candidates when its chunk manager creates structure state; the Echo generator handles its own candidates. Neither path mutates registry holders. Other dimensions are unaffected. These policies apply to normal generation, not operator `/place` commands or mods that bypass vanilla structure-state construction. Modded generators that require a concrete registry-lookup subtype need integration testing when policies are registered.

## Stability and fracture influence

`EchoStabilityManager.getStabilityAt(ServerLevel, BlockPos)` is the server-authoritative query. It composes a deterministic 256×256-block regional baseline with distance from known major fractures. It loads no chunks and creates no weather simulation.

| State | Default regional weight | Baseline intensity | Presentation |
| --- | ---: | ---: | --- |
| STABLE | 75 | 0.08 | Familiar terrain, wildlife, mostly ordinary audio and subtle tint |
| DESYNCED | 22 | 0.48 | Sampled vegetation gaps/open doors, quieter audio, stronger atmosphere |
| FRACTURED | 3 | 0.90 | Strong attenuation/tint, ash-like particles, greater Riftfall influence |

Fracture influence uses a smooth radial falloff. Active Temporal Rift coordinates project into Echo's shared horizontal coordinate system with full strength. Remembered major sites retain a lower peak strength of 0.8. This extends fracture effects without changing the existing rift's travel destination into The Before.

The persistent site ledger retains at most 128 distinct chunks, evicting the oldest sites when full. The query cache retains at most 1,024 chunk summaries for one second, sampled at chunk centers. `recordMajorFracture(level, position)` allows future authored fracture sites in either Earth to join this service. Temporary debug overrides affect queried regional state, not historical terrain decoration or discovery evidence.

Disabling stability returns neutral Echo atmosphere and restores the existing full-strength Riftfall eligibility. Disabling fracture influence leaves only regional variation. Generated-region weights are not retroactive: changing them later can change atmosphere and future decoration, but never redecorates old chunks.

## Reality echoes and player construction

`EchoBuildEchoManager` still samples successful solid-block placement/break events in the Overworld, retaining the original `wilderness_odyssey_echo_build_echoes` SavedData name and record format. Block entities, inventories, bedrock and rift/capsule blocks are excluded.

- Default placement sampling probability is 0.35; breaks use half that.
- Placement delay remains one to three game-time days; breaks use one to four.
- Eight-block fragments share a small offset: up to two blocks horizontally and zero to three blocks downward.
- Missing samples leave partial structures. Existing material categories become weathered/scarred materials, and log remnants can lie on different axes.
- At most 64 records are examined and 32 replacements attempted per second across the server.
- Destinations must already be loaded, within build height and inside the world border. The system acquires no chunk tickets.
- Repeated source edits coalesce. At the configured queue cap, new samples are declined while already accepted work remains.
- Due records expire after the configured retention period if they cannot be delivered. Placed blocks are never deleted by expiry.

New player edits in Echo mark a persistent chunk attachment, conservatively protecting that entire chunk from future material arrivals. Multi-block placement events mark each affected chunk. A player can build safely while unexplored/unmodified chunks remain eligible. Pre-upgrade player construction cannot always be distinguished from natural stone/soil; the existing conservative replacement whitelist still applies there. WorldEdit or other tools that bypass these events should explicitly mark their affected chunks through `ModAttachments.ECHO_CHUNK`.

Each affected chunk stores at most sixteen remnant positions/block IDs. A later explorer can earn material evidence by seeing an unchanged recorded remnant within sixteen blocks in their current loaded chunk. The observation checks visibility; buried or already removed remnants do not grant evidence merely because they were queued.

Legacy records remain readable, including records without a type field. Duplicate source positions coalesce to the last retained record. Exceptionally oversized legacy queues have a hard 65,536-record load cap with a warning; records beyond that safety cap are not retained. Normal admission defaults to 8,192.

## Generation decoration and wildlife

`EchoDimensionEvents` remains the event owner. Only new Echo chunks, with both stability and chunk distortion enabled, receive decoration. Stable regions receive none. Desynced/fractured regions sample up to sixteen columns and twenty-four vertical positions per column: **at most 384 sampled block states, 32 additional door-partner checks and 64 mutations**, instead of complete relevant-section scans. Doors open as a matching pair of halves.

Sampled doors may open and small leaf gaps may appear. This is intentionally sparse: not every village door or leaf cluster changes. Dynamic fracture movement never reruns this decoration. Reloaded chunks and subsequent player edits are preserved.

The existing natural-spawn allowlist remains configurable and includes wildlife and iron golems. Villagers, wandering traders and zombie villagers retain the existing removal rule. Compatible modded wildlife can be added through the allowlist.

## Riftfall and atmosphere

Riftfall retains its existing phase, weather, exposure, spawn and corrosion ownership. Echo stability scales start probability and exposure, gates eligible player locations, and scales sampled corrosion. Stable locations below 0.3 intensity do not gain the local exposure/spawn presentation of an unstable region. Existing dimension-wide phase transitions and meteor surge ownership remain with Riftfall; regional stability does not create independent storm clocks or rewrite the weather simulation.

The existing Echo and Riftfall client effects compose their color tints. Sound attenuation preserves instance identity, loops, streaming, user volume settings and stop behavior. Player, master/UI and voice categories are preserved. Long-running non-tickable audio may keep its start-time attenuation until Minecraft refreshes its volume; tickable sounds update normally.

The payload contains local intensity, region, presentation flags and time for stale-packet rejection. It excludes the world seed and fracture locations. Changes send at most once per second per Echo player, with a ten-second refresh. Client state is dimension-bound and cleared on travel/disconnect; server state clears on logout, dimension unload and shutdown. The mod's payload protocol version was advanced for this addition.

## Day, night and optional anomalies

The bundled dimension type removes `fixed_time`, uses `minecraft:overworld` effects and zero artificial ambient light. Echo now follows the server's existing daylight clock, including Wilderness Odyssey's existing day-length adjustments and daylight gamerule. It does not create a second ticking calendar or modify Overworld time.

Optional anomalies are disabled by default. When enabled, selected fractured regions briefly hold celestial presentation and then recover without permanent drift. Each effect uses forty celestial-time units for the hold and forty for recovery, so wall-clock duration follows the existing day-length behavior. No entities, redstone, crops, weather, scheduled ticks or saved game-time values are paused or skipped.

Beds, respawn anchors and raids retain their previous disabled settings. A data pack overriding Echo's dimension type can retain fixed time or a different sky renderer; the mod does not rewrite saved registry data or user packs.

## A.E.T.H.E.R. and Eclipse discoveries

`EchoDiscoveryManager` records compact evidence in the world's player-persistence lifecycle, independently of untrusted personal AI memories. Findings are independent bits: later evidence never fabricates a missing earlier observation.

1. Arrival: geological familiarity only.
2. Repeated correspondence: three distinct, already loaded matching Earth/Echo chunks, checking height and biome. No remote chunk loads are forced.
3. Independent history: `observeStructure(player)` is an explicit hook for authored divergent content. No region hash or generic ruin invents this history.
4. Material synchronization: a visible, actually applied remnant.
5. Alignment hypothesis: material evidence and a known fracture, presented as a hypothesis.

These tags feed the existing local fallback, prompt construction and standalone Aether backend prompt/verification path. Eclipse responds with the highest earned finding when asked; there is no unsolicited exposition broadcast on each discovery. Original-experiment records and Requiem's historical recovery remain future authored content.

The Overworld counterpart must already be loaded for geographical proof. A second player or an already loaded spawn area can supply that observation; an unavailable counterpart leaves the finding unknown. This deliberate limit avoids loading a second world during exploration.

## Development commands and validation

Permission level 2 is required:

```text
/wo echo stability
/wo echo stability stable
/wo echo stability desynced
/wo echo stability fractured
/wo echo stability reset
/wo echo syncinfo
```

Overrides affect the current 256-block region and clear on server shutdown. At most 128 overrides are retained. They require Echo Earth and an enabled stability system. The diagnostics expose dimension, region, local state/intensity, nearest known fracture, distance/influence and queue size to operators only.

Run sequentially, using JDK 21 and the existing wrapper:

```powershell
.\gradlew.bat compileJava '-PcodexBuildDir=.codex-build' --no-parallel
.\gradlew.bat echoTest '-PcodexBuildDir=.codex-build' --no-parallel
.\gradlew.bat :aether-server:test --tests com.thunder.aether.server.model.EchoPromptBoundaryTest '-PcodexBuildDir=.codex-build' --no-parallel
.\gradlew.bat build '-PcodexBuildDir=.codex-build' --no-parallel
```

`echoTest` uses the existing offline JUnit runtime for deterministic regions, falloff, fragment sampling, bounded/fair queues, legacy persistence, chunk protection/evidence, payload serialization, celestial recovery, structure policies and progressive fallback boundaries. The targeted backend test checks earned-evidence boundaries in both generation and verification prompts. Packaging does not imply that all tests ran: this repository's `build` task is configured separately from the full test suite.

Manual acceptance in a disposable world:

1. Enter through the existing route or `/wildernessrift teleport_echo`. Compare matching coordinates and observe the ordinary sun/moon cycle.
2. Use the three regional overrides. Check smooth fog/sky transitions, wildlife/block audio, ordinary player/voice sound and two-client agreement. Reset the override afterward.
3. In a new chunk, inspect sparse open-door/leaf effects. Edit doors/leaves, reload the chunk, and confirm no redecoration.
4. Build several small structures on Earth, allow game-time days to pass, then load the corresponding Echo chunks. Inspect partial weathered fragments and the queue diagnostics. Confirm incoming echoes do not alter a chunk edited in Echo.
5. Approach a visible recorded remnant and ask Eclipse about Echo Earth. Confirm material evidence; a new player must not know it in advance. Save/rejoin/respawn and confirm player-specific evidence persists.
6. In a disposable area, use the existing rift opening command (its sinkhole remains destructive by design), compare matching Echo coordinates at increasing distances, then close/restart and inspect the remembered site.
7. Test authored shared, Earth-only, Echo-only and variant sets in newly generated chunks, including ring placement and a missing optional variant. Verify modded biomes and structure providers with the actual pack.
8. Verify dedicated-server startup, client connection, disconnect/re-entry, resource reload, daylight gamerule and other sky/audio mods. Enable time anomalies only for the optional celestial check.

## Explicitly deferred

Final Echo facilities, settlements, accelerator complexes, roads, bunkers and civilization remnants; structure-specific history records; original experiment exposition; entity/redstone time manipulation; persistent floating terrain, large displaced landforms and new destructive fracture mechanics are not introduced here. Existing Temporal Rift terrain damage remains its own system.

No live gameplay, visual, multiplayer or performance result follows from source inspection, compilation, unit tests or packaging alone.
