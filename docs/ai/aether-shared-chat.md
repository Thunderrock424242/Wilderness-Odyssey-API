# Shared ordinary Aether chat

This additive implementation follows the reviewed local API Qwen migration `7f4bd3f6` and desktop revision `e9c0d22d`, paired with Wilderness-Odyssey's `bot` branch. It does not alter pinned `60a9620` playground contracts or native `/health`, `/ready`, `/v1/aether/generate`, `/v1/aether/status` and admission schemas. The gateway remains inference-only unless separately approved administration is configured. No model activation or training is performed by these routes.

- `POST /v1/aether/chat`: inference bearer; strict schema version `1.0`, UUID `requestId`, exact `security.minecraft_server_id` in `serverId`, `surface` (`discord` or `minecraft`), 64-character lowercase hexadecimal `principalId` and `scopeId`, `message` (nonblank, no NUL, at most 2000 UTF-16 characters). All fields required; unknown fields rejected.
- Success: exactly `schemaVersion: '1.0'`, echoed `requestId`, exact configured `serverId`, configured `model`, `success: true`, `response` (nonblank, no NUL, at most 2000 characters).
- `GET /v1/aether/chat/status`: inference bearer; returns exactly `schemaVersion: '1.0'`, configured `serverId`, `model`, `available`. It checks native commissioning, journal admission and cached model readiness. It does not measure capacity or prove real generation.

Both surfaces share native rate/admission limits, generation workers/queue, deadlines, cancellation on shutdown and metadata-only audit. Browser-origin headers and incorrect credential scopes are rejected by the existing service authenticator. Monitoring/admin/main-service credentials cannot authorize ordinary chat. Model, runtime address, system prompts and tools cannot be chosen by callers. HTTP errors are categorical; callers must not forward upstream details to users.

The chat adapter is stateless and has no memory lookup, profile export, training ingestion or actions. IDs are metadata only and never enter the prompt. It uses the server's canon and unrecovered-discovery boundaries without fabricating Minecraft player/world state. Draft and factual verifier share one deadline and require parsed JSON. Both explicitly disable Qwen thinking; no hidden reasoning is forwarded. Existing native Minecraft generation still uses its real player/world/history request and the same approved runtime.

Matching fixture: `aether-server/src/test/resources/aether-chat-v1.json` and bot `test/fixtures/aether-chat-v1.json`. Bot authority: `src/contracts/v1/aether-chat.ts`; API parser: `ChatRequest`. Tests exercise real gateway HTTP against mocked Ollama; those tests do not prove hosted deployment.

See bot `docs/aether-hosted-chat.md` for exact private environment variables, host discovery steps, Teacher/base verification, import, deployment, command registration and controlled live checks. `deploy/aether-inference.example.yml` is a disabled starting template: gateway and private Ollama must agree on context/output/concurrency, and native activation flags stay false pending measured admission. Preserve the operator's existing prompt files, credentials, storage and journal. Run `./gradlew -p aether-server check assemble` with JDK 21; deploy `aether-server/build/libs/Aether-Gateway.jar`, then restart through the existing host process manager.
